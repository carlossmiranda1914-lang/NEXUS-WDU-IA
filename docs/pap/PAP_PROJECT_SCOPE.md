# PAP Project Scope

## 1. Project identity

Nexus Edu IA is being developed as a real institutional school-management platform. The PAP documents and presents a truthful, bounded slice of that real product; it does not convert the product into a demo.

## 2. Scope classifications

Every capability referenced in the PAP must use one of these states:

```text
IMPLEMENTED_AND_PROVEN
IN_DEVELOPMENT
PLANNED
BLOCKED_BY_EXTERNAL_DEPENDENCY
OUTSIDE_PAP_SCOPE
```

## 3. Current PAP boundary

This document is the canonical place to state which Nexus capabilities are intended to be presented academically. Update it from repository evidence only.

For each included capability record:

```text
CAPABILITY=
PRODUCT_STATUS=
PAP_STATUS=
EVIDENCE_SOURCE=
LIMITATIONS=
EXTERNAL_DEPENDENCIES=
```

## 4. Product realism rule

Academic scope must never be used to justify fake data as product truth, disposable persistence, weakened security, browser-owned authority, simulated uploads or presentation-only backend behavior.

## 5. Incomplete product is acceptable when truthful

The PAP may present a robust subset of Nexus while other modules remain in development, planned or blocked by external dependencies. The report and presentation must explain these boundaries clearly rather than claim total platform completion.
