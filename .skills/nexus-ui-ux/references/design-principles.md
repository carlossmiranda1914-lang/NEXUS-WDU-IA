# Nexus design principles

1. **Task first.** Make the primary institutional task obvious; remove controls/content that do not help it.
2. **Truth before polish.** Display only states and capabilities supported by current backend contracts.
3. **One visual language.** Reuse existing tokens and components; avoid page-specific design systems.
4. **Hierarchy over decoration.** Use typography, spacing, grouping and alignment before borders, shadows or color.
5. **Low cognitive load.** Prefer progressive disclosure, clear labels and sensible defaults over dense control surfaces.
6. **Safe by design.** Make destructive/high-impact actions visually and procedurally distinct without relying on color alone.
7. **Institutional context is visible.** When context affects meaning or authority, make the active institution/scope understandable without exposing unnecessary identifiers.
8. **Responsive, not compressed.** Reflow priorities on narrow screens; do not merely shrink desktop layouts.
9. **Feedback is factual.** Show progress, success and failure at the point of action; reconcile successful mutations from backend truth.
10. **Consistency beats novelty.** A slightly less fashionable component that matches the product is preferable to a bespoke pattern.

Avoid gratuitous card grids, nested cards, excessive badges, tiny low-contrast metadata, icon-only critical actions, decorative gradients, permanent helper prose and animation without information value.
