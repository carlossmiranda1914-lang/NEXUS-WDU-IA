## Discovery method and limits

The inventory was produced from route registration, controller/service/repository tracing, direct Drizzle/SQL calls, client callers and local/browser/external writes. It covers every P0/P1 persistent mutation registered in `server.ts` and `src/modules/` at the baseline, plus client-side persistence and direct external writes. Dynamic runtime registration, real production traffic and external service credentials were deliberately not assumed. They remain explicit evidence gates before a fence.

## Caller graph conclusions

1. **Canonical vNext Enrollment** is separately mounted by `registerEnrollmentRoutes(app)` and uses institutional context/policies. Legacy enrolment endpoints are already explicit 410 fences, though `EnrollmentWorkspace` still calls the legacy draft endpoint and must be corrected only by an authorized future slice.
2. **School Tasks has competing code registrations.** `registerSchoolTaskRoutes(app)` is invoked before the legacy block in `server.ts`; matching modular handlers normally respond first. The legacy block still includes unique read/write-adjacent paths and direct SQL/Drizzle calls. Its effective reachability requires an Express integration trace—not a reference search—before a route is removed.
3. **Legacy direct routes are called through `src/supabaseClient.ts`** and some direct component fetches. Their browser callers do not make them canonical; they prove that a fence needs UI/direct-API regression coverage.
4. **AI and Google integrations are independent callers, not UI aliases.** They must be tested as direct API/external command paths.

## AC01 closure rule

## AI tool effect ledger

All `/api/chat` tools are enumerated above. The caller is the Gemini function-call loop after an authenticated HTTP request; it executes each returned function call without a human confirmation step. The route authenticates Firebase identity but does not resolve/use an institutional context for the tool dispatcher. `operational_logs` is appended by every listed read/write tool; it is audit evidence, not authorization. No tool uses a transaction that includes both its business mutation and audit log. No filesystem, outbound-message delivery or external API write was found in the dispatcher; legacy websocket broadcasts intentionally drop without institutional context.

## AC01 closure rule

AC01 is **closed for the 2026-08-24 baseline**: every discovered P0/P1 persistent write has a classification and treatment. No path is labelled DEAD from reference absence alone. Future code additions must reopen this matrix entry before implementation.
