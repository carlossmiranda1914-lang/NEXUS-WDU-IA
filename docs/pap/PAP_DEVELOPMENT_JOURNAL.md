# PAP Development Journal

Use this journal to record meaningful Nexus development events and learning. Do not log every commit or trivial change.

Each entry should be grounded in repository evidence and distinguish product truth from PAP explanation.

## Entry template

```text
DATE=
MODULE=
CAPABILITY=
PRODUCT_STATUS=
PAP_STATUS=

PROBLEM_IDENTIFIED=
WHY_IT_MATTERED=

ANALYSIS=
DECISION=

IMPLEMENTATION_SUMMARY=
DATABASE_IMPACT=
SECURITY_OR_AUTHORITY_IMPACT=
SCALE_CONSIDERATIONS=

EVIDENCE=
RESULT=

PROBLEMS_ENCOUNTERED=
HOW_THEY_WERE_RESOLVED=

KNOWN_LIMITATIONS=
EXTERNAL_DEPENDENCIES=

WHAT_I_LEARNED=
HOW_I_WOULD_EXPLAIN_IT_TO_THE_JURY=

REPOSITORY_REFERENCES=
```

## Rules

- Record only facts supported by code, tests, commits, UAT or canonical documentation.
- Do not describe planned work as implemented.
- Do not copy large implementation logs; summarize the engineering meaning.
- Link to Feature Records for capabilities that need deeper explanation.
- Update an existing entry when a later result changes its truthful status instead of creating contradictory narratives.
