# Mission 03 Progress — 2026-08-11

## Implemented and validated

- Migration `0004_vnext_institution_resource_ownership.sql` was applied to
  the official database. It stores one owning institution for every protected
  legacy resource.
- Institutional reads and writes are protected for announcements, messages,
  documents, approvals, students, teachers, users, and invoices.
- Sensitive mutations do not disclose a resource belonging to another
  institution: document/student deletion, invoice payment/cancellation, and
  approval transitions return not found outside the active institution.
- Documents generated by the assistant are assigned to the active institution
  before they can be listed.
- Financial reconciliation and forecasting are limited to invoices and students
  owned by the active institution.
- Legacy real-time broadcasts without verified institutional context are
  intentionally refused; school-task events use the tenant-scoped WebSocket
  manager.
- Two-institution negative tests, type checking, and production build passed.

## Closure decision

Mission 03 is complete. Every legacy route that returns or mutates an
institutional record now has an ownership boundary, and unscoped real-time
events are refused instead of broadcast globally. Future real-time additions
must call the tenant-scoped WebSocket manager with the backend-resolved
institution identifier.

## Non-negotiable rule

A record without a verified ownership mapping is inaccessible from an
institutional API. The client never proves or selects the institution.
